Scope and constraints

What the system is designed to optimize.

Nooklet favors operability for a self-hosted instance over distributed scale. The architecture keeps one deployment unit while maintaining explicit domain boundaries, persisted workflow state, and recoverable failure semantics inside that unit.

QA-01

Explainability

Every blocked action should identify the checked resource, observed state, and corrective action.

QA-02

Recoverability

Request, queue, import, job, and audit state survive process restarts in SQLite.

QA-03

Constrained trust

Secrets, outbound hosts, persisted result ownership, and filesystem roots are policy-bound.

QA-04

Low operational load

One container owns the web runtime, worker, download engine, migrations, and health surface.

Runtime and dependency architecture

One deployment unit. Explicit internal boundaries.

Next.js handles delivery and authenticated interaction. Named workflows own use cases. Repositories own transactions. Typed adapters own protocols. The worker and native downloader share the same process, but their durable state remains outside process memory.

Runtime startup

Database first, then worker.

src/instrumentation.ts initializes the runtime. ensureDatabaseReady opens SQLite and applies the migration journal; the background worker then begins its 15-second loop.

HTTP surface

Small by design.

Most mutations use authenticated server actions. Three API route files cover narrow HTTP concerns, including health, rather than exposing a generic CRUD or upstream proxy API.

Domain ownership

Workflows are the unit of change.

The repository contains 142 production workflow files and 80 workflow test files across request, search, scan, import, recommendation, connection, and history domains.

Request, transfer, and import

A persisted sequence, not a button-to-vendor shortcut.

The request path validates intent and ownership before acquisition, reserves local state before submission, compensates partial writes, and converges built-in and legacy downloads on one conservative import pipeline.

Persistence and data integrity

Workflow state is normalized and independently auditable.

Forty Drizzle tables separate intent, queue state, transfer state, import evidence, recommendations, history, jobs, notifications, credentials, and audit events. SQLite-specific behavior is embraced deliberately rather than hidden behind portability claims.

Write invariants

Database-enforced uniqueness

  • One active request per user, title, and episode/season key.
  • One job per user, type, target type, and target key.
  • One queue item per client and external queue identifier.
  • One normalized watch-history item per source and media key.

Migration contract

Journal plus compatibility checks

ensureDatabaseReady applies the Drizzle journal when its signature changes, then performs narrowly scoped compatibility repairs and asserts the expected schema.

Concurrency and recovery

Persist ownership; assume the process can disappear.

The worker remains in-process, but job ownership is not inferred from memory. Compare-and-set claims, random run tokens, expiring leases, heartbeats, and token-checked completion make stale work reclaimable.

Failure isolation

Promise.allSettled, not fail-fast.

An optional integration failure does not prevent unrelated job types or built-in import work from making progress. Failure context is persisted and reflected in health.

Design constraint

The completed-import mutex and engine runtime are process-local. This is correct for the declared single-process deployment, but it is not a distributed lock and should not be presented as multi-replica safe.

Security architecture

Trust is narrowed at every edge.

Nooklet treats browser input, configured service hosts, persisted result URLs, downloaded archives, and filesystem paths as separate trust boundaries. Controls are layered around the actual data flow.

Identity

Live-account session checks

Passwords use scrypt and timing-safe comparison. Login and bootstrap are throttled. Disabled users and password changes invalidate otherwise live sessions; temporary passwords require replacement.

Secrets

Versioned authenticated encryption

AES-256-GCM envelopes use HKDF-SHA256-derived keys. A dedicated SECRET_BOX_KEY is preferred, and previous keys support lazy read-and-rewrite rotation.

Outbound network

Validate, resolve, then pin.

safeFetch permits HTTP(S), rejects URL credentials, classifies all resolved addresses, pins validated DNS results, refuses redirects, and enforces duration and body limits.

Filesystem + archives

Canonical containment before mutation.

Media roots fail closed when unconfigured. Filesystem roots, device/network paths, symlinks, escaped files, unsafe archive entries, and unbounded extraction trees are rejected.

Assurance boundary

These controls are source-backed defense in depth, not a penetration test or independent security certification. TLS termination, ingress policy, mount permissions, backup retention, and off-host protection remain operator responsibilities.

Deployment and operations

A compact runtime with explicit persistence.

The production image is multi-stage and runs as a non-root user behind tini. Compose drops Linux capabilities, enables no-new-privileges, binds to loopback by default, and makes persistent/mounted state visible.

Observe

/api/health

Database failure or a stale/stopped worker returns 503. A healthy or optionally degraded worker remains observable without falsely failing the container.

Protect

Verified online backup

The source and completed copy both pass SQLite quick_check; the command refuses overwrite and restricts permissions where supported.

Package

Sanitized standalone output

Source, tests, environment files, local databases, private keys, and local tooling state are removed; every journaled migration must remain.

Recover

Scoped admin reset

The recovery command resets one selected local administrator, clears lockout state, audits the event, and requires password replacement.

Evidence limits

The repository does not currently evidence an SBOM, signed image, automated restore drill, performance benchmark, browser E2E suite in CI, or immutable action/image digests. Workflow execution does not by itself prove branch-protection configuration.

Engineering conclusion

The system is small by deployment count, not by hidden responsibility.

Nooklet keeps operational topology compact while making boundaries, persistence, recovery, trust, and failure semantics explicit. The result is a self-hosted system that can explain what it is doing and leave enough evidence to diagnose what happened.

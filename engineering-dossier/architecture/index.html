Breakdown 01

Writes re-establish trust at their entry point.

Nooklet exposes three HTTP route files. Most mutations travel through sixteen "use server" files across src: fifteen under src/app, plus the layout sign-out action. The built-in queue's authenticated POST handler is the deliberate HTTP exception. Each protected entry point authenticates, validates its input, and delegates to a focused module operation.

Owning source

  • src/proxy.ts
  • src/app/(workspace)/settings/connections/actions.ts
  • src/auth.ts
  • src/lib/security/rate-limit.ts
  • src/modules/service-connections/workflows/save-service-connection.ts
  • src/lib/database/client.ts

Breakdown 02

Server-rendered reads do not make an HTTP hop.

A server component imports a module query as an ordinary function and calls it during render. There is no fetch, no serialization boundary, and no endpoint in between. The three route files that do exist serve authentication callbacks, the container health probe, and the caller-scoped queue API used for polling and controls.

Owning source

  • src/app/(workspace)/library/page.tsx
  • src/modules/media-library/queries/
  • src/app/api/health/route.ts
  • src/app/api/downloads/queue/route.ts

Breakdown 03

A module publishes three folders and hides four.

commands/, queries/, and workflows/ are the public surface. Repositories, adapters, schemas, and types are internal, reached only through that surface. Folders are created when real code lands, so most modules carry a subset rather than the full template.

Owning source

  • docs/architecture/project-structure.md
  • src/modules/jobs/public.ts
  • scripts/validate-module-boundaries.mjs
  • src/app/(workspace)/library/actions.ts
  • src/lib/jobs/web-action-offload.test.ts

Breakdown 04

A workflow orchestrator only names the order.

The canonical shape is a folder of phase files behind a thin index.ts that awaits each one in sequence and branches nowhere. Indexer search is the cleanest example in the repository: eight phases, thirty-three lines, no conditionals.

Owning source

  • src/modules/downloads/workflows/season-fulfillment.ts
  • docs/adr/ADR-0003-durable-season-fulfillment.md

Breakdown 05

One container, one supervisor, three long-lived children.

A wedged bind mount blocks in the kernel and cannot be cancelled from JavaScript. Enough blocked calls exhaust the process-wide filesystem thread pool and page rendering stops. The answer is process isolation: filesystem work never runs in the web runtime.

Owning source

  • scripts/container-supervisor.mjs
  • scripts/lib/worker-heartbeat-watchdog.mjs
  • scripts/lib/storage-probe-coordinator.mjs
  • src/lib/jobs/worker-entry.ts
  • docs/adr/ADR-0004-isolate-filesystem-work-from-web-runtime.md

Breakdown 06

Filesystem lanes run alone; network lanes run together.

Every fifteen seconds the worker runs one pass. The three lanes that touch the filesystem execute serially and first, then maintenance runs by itself, and only then do the four network and AI lanes run concurrently.

Owning source

  • src/lib/jobs/worker.ts
  • src/modules/jobs/repositories/job-repository.ts
  • src/lib/jobs/worker-heartbeat.ts
  • src/lib/jobs/worker-readiness.ts

Breakdown 07

The download engine drains one release at a time.

Admission happens in the web process against a persisted capacity snapshot. Everything after that runs in the worker: a single drain loop claims one queued row, fetches every segment over a pool of NNTP connections, and writes decoded payloads straight into the assembling file at their byte offsets.

Owning source

  • src/modules/download-engine/runtime/engine-runner.ts
  • src/modules/download-engine/runtime/live-capacity.ts
  • src/modules/download-engine/scheduler/download-nzb.ts
  • src/modules/download-engine/finalize/finalize-download.ts
  • docs/adr/ADR-0002-in-house-download-engine.md

Breakdown 08

Eight states are declared; seven are reachable.

The engineDownloadStates enum lists eight values, and every state transition is a compare-and-swap that names the states it expects to find. One of the eight is never written by any code path.

Owning source

  • src/lib/database/schema.ts
  • src/modules/download-engine/queue/engine-repository.ts
  • src/modules/download-engine/queries/get-engine-queue-snapshot.ts

Breakdown 09

Forty-five tables in one SQLite file.

One schema file declares every table. Most entity rows use text identifiers and millisecond timestamps; relationship tables use composite or parent keys, and foreign keys declare explicit delete behavior. Service credentials live in dedicated side tables instead of parent rows.

Owning source

  • src/lib/database/schema.ts
  • src/auth.ts
  • drizzle/

Breakdown 10

The web process never calls statfs.

A hung mount blocks in the kernel and takes the filesystem thread pool with it. So the request path reads a persisted snapshot instead, refreshed on a schedule by a disposable child process that can be killed at a deadline.

Owning source

  • src/modules/download-engine/workflows/enqueue-nzb-download.ts
  • src/modules/storage/workflows/refresh-storage-snapshots.ts
  • src/modules/storage/storage-snapshot-status.ts
  • src/modules/download-engine/runtime/live-capacity.ts

Breakdown 11

Four boundaries, each enforced at the point of use.

Stored credentials, outbound requests, filesystem paths, and abuse controls each have a dedicated module in src/lib/security/. None of them are middleware; every one is called by the code that is about to do the dangerous thing.

Owning source

  • src/lib/security/secret-box.ts
  • src/lib/security/safe-fetch.ts
  • src/lib/security/isolated-filesystem-policy.ts
  • src/lib/security/rate-limit.ts

Breakdown 12

Every repository opens the database the same way.

There is no exported connection singleton. Each caller invokes ensureDatabaseReady(), which is cheap after the first call and carries the migration gate, the pragma set, and a compatibility assertion with it.

Owning source

  • src/lib/database/client.ts
  • src/lib/env.ts
  • src/instrumentation.ts
  • Dockerfile

Appendix

Where the documentation and the code disagree.

Every row below is a claim you will find in a decision record, a structure document, or a type union, that the current implementation does not support. They are listed rather than quietly corrected so that reading an ADR does not mislead you.

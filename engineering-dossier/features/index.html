The complete loop

From “what should we watch?” to “it is in the library.”

Nooklet keeps each transition visible. A queued download is not presented as a completed request; availability is only confirmed after import and library reconciliation.

  1. 01
    Discover

    Browse current titles, search directly, or ask an optional AI provider for ideas.

  2. 02
    Choose scope

    Request a movie, a complete season, or selected episodes into the right destination.

  3. 03
    Acquire

    Search verified Newznab sources and send a compatible release to the native engine or SABnzbd.

  4. 04
    Recover

    Retry eligible failures, preserve progress, and surface repair steps when infrastructure blocks the plan.

  5. 05
    Organize

    Verify, repair, extract, safely import, scan, and record the final file as available.

Core capabilities

Everything needed for a calm, understandable media operation.

Core request functionality stays independent of recommendations, history, notifications, and external library context. Add the optional pieces that improve your household without turning them into prerequisites.

Discover

Find something worth watching.

Search TMDB, browse filtered catalog views, inspect artwork and context, and generate personal ideas through any compatible AI provider.

  • Movie and TV title search
  • Trending and filtered discovery
  • Optional taste-aware recommendations
  • Cast, trailers, genres, and providers

Library

Know what you actually own.

Scan movie and TV destinations, reconcile files with title records, monitor wanted content, and keep availability grounded in the filesystem rather than download intent.

  • Separate movie and TV destinations
  • Existing-library scans
  • File-aware availability
  • Monitoring and rescan jobs
03

Requests

Ask for exactly the right scope.

Select a title, season, or episode, review its destination and releases, and follow one durable request through search, queue, transfer, processing, and import.

  • Movie, season, and episode scope
  • Owned search-result records
  • Duplicate active-work protection
  • One Activity timeline
04

TV resilience

A season is an outcome, not one fragile pack.

Nooklet tries alternate complete-season releases for eligible content failures, then automatically falls back to missing aired episodes. Completed work is preserved while unavailable episodes wait.

  • Up to three physical pack attempts
  • Automatic per-episode fallback
  • Independent episode retry schedules
  • Restart-safe plan state and retry timing
05

Download engine

Usenet is built in.

Connect directly to a news server, persist queue state in Nooklet, control queued work, and let the container perform PAR2 verification, repair, and archive extraction.

  • Direct NNTP with TLS support
  • Pause, resume, and cancellation controls
  • Persisted queue state and failure reasons
  • Optional SABnzbd alternative
06

Storage + import

Paths and capacity are explicit.

See the effective staging filesystem, available space, active reservation, and final destinations. Imports remain inside approved canonical roots and refuse unsafe traversal or silent overwrite.

  • Container-path guidance
  • Conservative capacity preflight
  • Approved media and download roots
  • Collision-aware organization
07

Operations

Operate without guesswork.

Setup Center evaluates the real request path. Health, storage, jobs, audit history, and Activity turn failures into bounded states with the next corrective action.

  • Capability-level readiness
  • Worker and database health
  • Persisted automation jobs
  • Verified database backup tooling
08

Shared instance

Useful for a household, controlled by an admin.

Administrators own infrastructure and shared services. Managed users can discover and request without receiving access to service credentials or instance-wide configuration.

  • Local accounts and role boundaries
  • Encrypted saved credentials
  • User-scoped personal history
  • Discord, Apprise, and webhooks

Designed for the awkward cases

When the obvious download fails, the request keeps its purpose.

Nooklet separates the user’s desired outcome from individual release attempts. Content failures can advance automatically; storage, credentials, paths, or service failures pause with a repair action instead of generating a storm of doomed episode requests.

Clear fit, honest boundaries

Built for a self-hosted instance, not disguised infrastructure sprawl.

Nooklet deliberately optimizes for a compact household or personal deployment. Knowing the boundary is part of a frustration-free experience.

A strong fit

You want one understandable media workspace.

  • A single self-hosted application container
  • Usenet acquisition through Newznab sources
  • Movies and TV organized into mounted libraries
  • Explicit health, storage, and recovery states

Know before installing

Some operational choices remain yours.

  • Torrent transport is not implemented.
  • The built-in engine processes one release globally at a time.
  • Interrupted native transfers restart rather than resume by segment.
  • TLS termination, mount permissions, and off-host backups are operator responsibilities.
  • Horizontal multi-replica deployment is not supported.

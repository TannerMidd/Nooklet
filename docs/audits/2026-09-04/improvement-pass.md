# Improvement pass — implementation and acceptance ledger

Date: September 4, 2026. Baseline: `bdbe90b`. This pass implements the findings in the [original audit](report.md), which remains a record of the earlier behavior. Implementation and verification were completed locally before the separately requested alpha deployment and pull request preparation. The tests used isolated data; no production database migration, credential rotation, or production media operation was part of those tests.

The work preserves the existing application architecture and visual system. It concentrates on recoverable download state, protected configuration, atomic persistence, truthful UI feedback, capability-specific setup, and bounded YouTube queries. All 21 reported findings and seven UX opportunities have corresponding implementations and acceptance evidence below. Independent reviews accepted the final source scopes; operational recovery and release validation remain explicitly listed.

## Additional issues tracked during implementation

- **Interrupted imports:** immutable attempt journals now live outside engine artifact sweeps. Publication has an adjacent claim; failed or uncertain imports retain final media instead of unlinking it. Exact committed import/file rows authorize claim cleanup and source consumption. Restart recovers journals before engine cancellation and cleanup. Health reports retained, orphaned, malformed, and cleanup-pending output without exposing another user's paths.
- **Recovery after long use:** a rebuildable SQLite metadata catalogue excludes completed history from bounded recovery pages and preserves its cursor across restarts. Direct per-download checks remain independent of global pagination and unrelated malformed journals. Health filters by user and unresolved state before its limit, exposes accurate totals and discovery failures, and never advances recovery. Healthy reconciliation preserves progress; failed catalogues and their SQLite sidecars are retained. Ordinary calls also repair a catalogue that becomes unusable during worker operation, with concurrent callers sharing one rebuild.
- **Cancellation and durability retries:** ordinary worker ticks now reconcile non-active cancellations after startup, including cleanup retries. Existing journal plans, receipts, and committed markers must complete their required file sync before retry can publish, acknowledge persistence readiness, or consume source media. Parseable JSON alone is insufficient. Nine fresh-process filesystem/SQLite fault phases passed.
- **Catalog tracking after partial queue results:** recommendation history records a title as tracked once its catalog entry exists, independently of whether every download queued.
- **Stale terminal writes:** history replacement and the matching pending run's completion now share a transaction, guarded by user, source, and media type. A newer successful run supersedes older publication; a newer pending run does not erase a valid older result. A losing recommendation failure cannot emit a notification. Independent review accepted these corrections.
- **UI review follow-ups:** request action errors return feedback; every tab has a real panel target; pending monitoring cannot carry failed selections into another season. Closed connection cards show retest feedback, model and cookie controls reference their errors, alerts use valid container markup, and storage/health links preserve the originating search or setup context.
- **Mobile bulk actions:** the previous retry bar exceeded the viewport. The bar and season controls now wrap; failure feedback stays with the retry buttons. Both retry states fit at 390px and 320px. Successful retry clears selection and announces the result.
- **Library card counts:** movie/TV totals now include unassigned catalog titles and their files. Folder-specific storage counts keep their existing meaning. Real SQLite tests cover unassigned media and user isolation; the browser's TV card now agrees with its destination list.

## Operational and product follow-ups

1. Replace legacy credential-bearing URLs through the repair UI. Assess historic audit/backups privately and rotate affected credentials as appropriate. This pass does not inspect or destructively rewrite production credentials/audits.
2. Inspect quarantined legacy output and retained import journals before manual recovery. A journal identifies the request, attempt, source, and destination; its adjacent claim deliberately blocks scanning that source until ownership and completion are resolved. Verified retries can reuse an attempt. Uncertain or replaced output requires operator inspection; this pass does not automatically delete final library files or discard claims merely to clear an alert.
3. Re-sync/re-import history whose titles were dropped by old identity collisions. Normalization cannot reconstruct records never retained.
4. Validate live services, actual media import, Linux/container interruption, NAS failures, representative workloads, and assistive technology before release. Windows directory fsync uses an explicit fallback where unsupported; no untested power-loss guarantee is claimed.
5. Decide shared Plex/Tautulli profile permissions and worker-stall termination policy separately. Existing behavior is preserved; neither has an established replacement policy in this audit.

No dependency upgrade or application database migration was required. The new engine metadata catalogue is rebuildable from the retained journals and is separate from the application database.
